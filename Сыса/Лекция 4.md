## ЧАСТЬ 1: КОЛЛЕКТИВНОЕ ВЗАИМОДЕЙСТВИЕ

Коллективные операции — это операции, которые должны быть вызваны **всеми** процессами коммуникатора. Даже если процесс не участвует в передаче данных (например, не является корневым), он всё равно обязан вызвать функцию.

### 1. Широковещательный обмен (Broadcast)
**Функция:** `int MPI_Bcast(void *buf, int count, MPI_Datatype type, int root, MPI_Comm comm);`

*   **Назначение:** Передача данных от одного (корневого) процесса всем остальным процессам коммуникатора.
*   **Параметры:**
    *   `buf` — адрес начала буфера с данными.
    *   `count` — количество элементов в буфере.
    *   `type` — тип данных (например, `MPI_INT`, `MPI_DOUBLE`).
    *   `root` — номер корневого процесса, который является источником данных.
    *   `comm` — коммуникатор.
*   **Важно:** Буфер `buf` имеет разное назначение для разных процессов:
    *   Для **корневого** процесса (`root`) — это буфер **отправки** (содержит данные).
    *   Для **всех остальных** — это буфер **приема** (данные будут записаны в него).
*   **Особенность:** Все процессы должны вызвать эту функцию, иначе программа зависнет.

### 2. Операции редукции (Reduction)
**Функция:** `int MPI_Reduce(void *sendbuf, void *recvbuf, int count, MPI_Datatype type, MPI_Op op, int root, MPI_Comm comm);`

*   **Назначение:** Сбор данных со всех процессов, выполнение над ними заданной операции (например, сложения) и помещение результата в один (корневой) процесс.
*   **Параметры:**
    *   `sendbuf` — буфер с данными, которые процесс отправляет.
    *   `recvbuf` — буфер для результата (значим **только** для корневого процесса).
    *   `count` — число элементов.
    *   `type` — тип данных.
    *   `op` — операция редукции (см. таблицу ниже).
    *   `root` — номер процесса, который получит результат.
    *   `comm` — коммуникатор.
*   **Требования:** Все процессы должны передать одинаковые значения `count`, `type`, `op`, `root`, `comm`. Результат получает только корневой процесс.

#### Базовые операции редукции (MPI_Op):
| Операция | Описание |
| :--- | :--- |
| `MPI_MAX` | Вычисление максимального значения |
| `MPI_MIN` | Вычисление минимального значения |
| `MPI_SUM` | Вычисление суммы значений |
| `MPI_PROD` | Вычисление произведения значений |
| `MPI_LAND` | Логическое «И» |
| `MPI_BAND` | Побитовое «И» |
| `MPI_LOR` | Логическое «ИЛИ» |
| `MPI_BOR` | Побитовое «ИЛИ» |
| `MPI_LXOR` | Логическое исключающее «ИЛИ» |
| `MPI_BXOR` | Побитовое исключающее «ИЛИ» |
| `MPI_MAXLOC` | Максимальное значение и его индекс |
| `MPI_MINLOC` | Минимальное значение и его индекс |

> *Примечание лектора:* Начиная с 3-го стандарта MPI, можно также передавать указатель на пользовательскую функцию для выполнения нестандартных операций редукции.

### 3. Пример: Вычисление числа π
**Задача:** Вычислить интеграл \(\pi = \int_{0}^{1} \frac{4}{1+x^2} dx\) методом прямоугольников.

**Схема параллелизации:**
1.  Корневой процесс (Rank 0) запрашивает количество интервалов `n`.
2.  Значение `n` рассылается всем процессам через `MPI_Bcast`.
3.  Каждый процесс вычисляет свою часть суммы. Используется **циклическая схема**: процесс `i` обрабатывает интервалы с шагом `ProcNum` (например, процесс 0: 1, 3, 5...; процесс 1: 2, 4, 6...).
4.  Локальные суммы (`mypi`) собираются на корневом процессе через `MPI_Reduce` с операцией `MPI_SUM`.
5.  Корневой процесс выводит результат и время выполнения.

**Ключевые строки кода:**
```c
MPI_Bcast(&n, 1, MPI_INT, 0, MPI_COMM_WORLD);
// ... вычисление локальной суммы mypi ...
MPI_Reduce(&mypi, &pi, 1, MPI_DOUBLE, MPI_SUM, 0, MPI_COMM_WORLD);
```

### 4. Рассылка и сбор данных (Scatter / Gather)

#### Рассылка (Scatter)
**Функция:** `int MPI_Scatter(void *sbuf, int scount, MPI_Datatype stype, void *rbuf, int rcount, MPI_Datatype rtype, int root, MPI_Comm comm);`

*   **Назначение:** Разбиение данных на корневом процессе на равные части и рассылка их остальным процессам.
*   **Особенности:**
    *   Корневой процесс передает сообщения одинаковой длины (`scount`) из буфера `sbuf`.
    *   Каждый процесс (включая корневой) получает сообщение длины `rcount` в буфер `rbuf`.
    *   Обычно `scount == rcount`.
*   **Разновидность:** Если размеры сообщений для разных процессов различаются, используется `MPI_Scatterv()`.

#### Сбор (Gather)
**Функция:** `int MPI_Gather(void *sbuf, int scount, MPI_Datatype stype, void *rbuf, int rcount, MPI_Datatype rtype, int root, MPI_Comm comm);`

*   **Назначение:** Операция, обратная рассылке. Сбор данных со всех процессов на один (корневой).
*   **Особенности:**
    *   Корневой процесс получает от всех процессов сообщения одинаковой длины (`rcount`) в буфер `rbuf`.
    *   Каждый процесс (включая корневой) передает данные длины `count` из буфера `buf`.
*   **Разновидность:** Для сообщений разной длины используется `MPI_Gatherv()`.

### 5. Пример: Вычисление скалярного произведения
**Задача:** Вычислить \(S = \sum_{i=1}^{n} a_i \cdot b_i\).

**Схема параллелизации:**
1.  Корневой процесс инициализирует векторы `a` и `b`.
2.  Количество элементов `n` рассылается через `MPI_Bcast`.
3.  Вычисляется размер блока `n = n / ProcNum`.
4.  Данные векторов рассылаются по процессам через `MPI_Scatter`.
5.  Каждый процесс вычисляет частичное скалярное произведение своей части векторов.
6.  Результаты собираются на корневом процессе через `MPI_Reduce` с операцией `MPI_SUM`.

### 6. Взаимодействие «Каждый к каждому» (Allgather / Alltoall)

*   **`MPI_Allgather`:** Сбор данных со всех процессов, но результат получают **все** процессы (а не только корневой). Каждый процесс получает одинаковый массив данных.
    *   `int MPI_Allgather(void *sbuf, int scount, MPI_Datatype stype, void *rbuf, int rcount, MPI_Datatype rtype, MPI_Comm comm);`
    *   Для разного размера сообщений: `MPI_Allgatherv()`.

*   **`MPI_Alltoall`:** Каждый процесс отправляет данные каждому другому процессу, и каждый получает данные от каждого.
    *   `int MPI_Alltoall(void *sbuf, int scout, MPI_Datatype stype, void *rbuf, int rcount, MPI_Datatype rtype, MPI_Comm comm);`
    *   Для разного размера сообщений: `MPI_Alltoallv()`.

*   **`MPI_Allreduce`:** Редукция, результат которой получают **все** процессы.
    *   `int MPI_Allreduce(void *sendbuf, void *recvbuf, int count, MPI_Datatype type, MPI_Op Op, MPI_Comm comm);`

### 7. Синхронизация вычислений (Barrier)
**Функция:** `int MPI_Barrier(MPI_Comm comm);`

*   **Назначение:** Создание точки синхронизации. Процесс приостанавливается, пока все процессы коммуникатора не вызовут эту функцию.
*   **Применение (из лекции):** Используется для синхронизации замеров времени. Если нужно замерить время на разных процессах, вызов `MPI_Barrier` перед замером гарантирует, что все процессы начнут отсчет одновременно.
*   **Особенность:** Коллективная операция, должна быть вызвана всеми процессами.

## ЧАСТЬ 2: ВЗАИМОДЕЙСТВИЕ МЕЖДУ ДВУМЯ ПРОЦЕССАМИ (ПАРНОЕ)

Парные операции — это обмен данными между двумя конкретными процессами (отправителем и получателем).

### 1. Режимы взаимодействия (Режимы отправки)

В MPI существует 4 режима отправки сообщений. Все они используют один и тот же приемник — функцию `MPI_Recv`.

#### А. Стандартный режим (Standard)
**Функция:** `MPI_Send()`
*   **Логика:** Отправляющий процесс копирует сообщение во внутренний системный буфер MPI и завершает работу. Буфер пользователя можно использовать повторно.
*   **Гарантии:** Нет гарантий, что сообщение доставлено или принято. Оно может быть в процессе передачи, храниться в буфере получателя или уже принято.
*   **Блокировка:** Функция блокирующая (процесс ждет завершения копирования).
*   **Риск:** Если системный буфер переполнен, `MPI_Send` может заблокироваться до тех пор, пока получатель не начнет читать данные.

#### Б. Синхронный режим (Synchronous)
**Функция:** `MPI_Ssend()`
*   **Логика:** Функция завершается только после того, как получатель подтвердит **начало** приема сообщения (вызовет `MPI_Recv`).
*   **Гарантии:** Самый надежный режим. Отправитель знает, что получатель жив и начал прием.
*   **Блокировка:** Блокирующая, может ждать долго.
*   **Применение:** Рекомендуется для длинных сообщений, где важна надежность.

#### В. Режим «по готовности» (Ready)
**Функция:** `MPI_Rsend()`
*   **Логика:** Отправка происходит только тогда, когда получатель **уже** инициировал прием (вызвал `MPI_Recv`).
*   **Гарантии:** Самый быстрый режим, так как нет накладных расходов на подтверждение.
*   **Блокировка:** Блокирующая, но завершается быстро.
*   **Риск:** Если получатель не готов, поведение неопределенно (ошибка).
*   **Применение:** Редко используется, так как сложно гарантировать готовность получателя. *Совет лектора:* Можно использовать `MPI_Barrier` для синхронизации перед `MPI_Rsend`, но это неэффективно, если процессов больше двух.

#### Г. Буферизированный режим (Buffered)
**Функция:** `MPI_Bsend()`
*   **Логика:** Пользователь сам выделяет буфер в памяти для сообщений. `MPI_Bsend` копирует сообщение в этот буфер и сразу завершается.
*   **Гарантии:** Буфер пользователя свободен сразу после вызова. Системный буфер не переполняется.
*   **Требования:**
    1.  Выделить память под буфер.
    2.  Зарегистрировать его: `int MPI_Buffer_attach(void *buf, int size);`
    3.  После использования отсоединить: `int MPI_Buffer_detach(void *buf, int *size);`
*   **Применение:** Для коротких сообщений, когда нужно избежать блокировки.

#### Сводка по режимам:
*   **Ready:** Самый быстрый, но сложный в реализации.
*   **Standard / Buffered:** Компромиссный вариант, хорош для коротких сообщений.
*   **Synchronous:** Самый медленный, но самый надежный. Для длинных сообщений.

### 2. Неблокирующее взаимодействие (Non-blocking)

**Идея:** Функции обмена данными не блокируют процесс, позволяя ему выполнять вычисления параллельно с коммуникацией.

**Имена функций:** Отличаются префиксом `I` (Immediate):
*   `MPI_Isend()`, `MPI_Issend()`, `MPI_Ibsend()`, `MPI_Irsend()`, `MPI_Irecv()`.

**Параметры:** Добавляется последний параметр — `MPI_Request *request` (дескриптор операции).

**Проверка завершения:**
*   **`MPI_Test`:** Неблокирующая проверка.
    *   `int MPI_Test(MPI_Request *request, int *flag, MPI_Status *status);`
    *   `flag` = true (ненулевое), если операция завершена.
*   **`MPI_Wait`:** Блокирующее ожидание завершения.
    *   `int MPI_Wait(MPI_Request *request, MPI_Status *status);`

**Схема совмещения вычислений и обмена:**
```c
MPI_Irecv(buf, count, type, dest, tag, comm, &request);
do {
    // ... полезные вычисления ...
    MPI_Test(&request, &flag, &status);
} while (!flag);
```

**Дополнительные функции для множества запросов:**
*   `MPI_Testall` / `MPI_Waitall` — для всех операций.
*   `MPI_Testany` / `MPI_Waitany` — для любой одной операции.
*   `MPI_Testsome` / `MPI_Waitsome` — для некоторых операций.

### 3. Совмещенные прием и передача (Sendrecv)

**Функция:** `int MPI_Sendrecv(...)`
*   **Назначение:** Эффективное выполнение одновременной отправки и приема данных между двумя процессами. Позволяет избежать взаимоблокировки (deadlock), которая возможна при использовании двух `MPI_Send` и `MPI_Recv`.
*   **Параметры:** Объединяет параметры `MPI_Send` и `MPI_Recv`.
*   **Разновидность:** `MPI_Sendrecv_replace()` — если типы сообщений одинаковы, можно использовать один буфер.

### 4. Неблокирующее взаимодействие (Завершение)

**Схема работы:**
1.  Вызывается неблокирующая функция (например, `MPI_Irecv`). Она формирует дескриптор операции — `MPI_Request` — и сразу возвращает управление.
2.  Программа может выполнять полезные вычисления, пока данные передаются в фоне.
3.  Периодически вызывается `MPI_Test` для проверки статуса. Если операция завершена (флаг ≠ 0), цикл прерывается.
4.  Если работы больше нет, вызывается блокирующая функция `MPI_Wait`, чтобы гарантированно дождаться завершения операции.

> *Важно:* Такая схема часто используется в итерационных методах, где можно совместить вычисления с обменом данными. Это усложняет код, но может дать существенный выигрыш по времени.

**Функции для работы с множеством запросов:**
*   `MPI_Testall` / `MPI_Waitall` — проверяют/ожидают завершения **всех** перечисленных операций.
*   `MPI_Testany` / `MPI_Waitany` — проверяют/ожидают завершения **хотя бы одной** операции.
*   `MPI_Testsome` / `MPI_Waitsome` — проверяют/ожидают завершения **некоторых** операций из списка.

### 5. Совмещенные прием и передача (MPI_Sendrecv)

**Проблема:** Если два процесса одновременно вызовут `MPI_Send` друг другу, может возникнуть **взаимоблокировка (deadlock)**. Оба процесса будут ждать, пока другой начнет прием, и ни один не сможет завершить отправку.

**Решение:** Функция `MPI_Sendrecv`.
*   **Назначение:** Выполняет одновременную отправку и прием данных между двумя процессами.
*   **Параметры:**
    *   Параметры для отправки: `sbuf`, `scount`, `stype`, `dest`, `stag`.
    *   Параметры для приема: `rbuf`, `rcount`, `rtype`, `src`, `rtag`.
    *   `comm` — коммуникатор.
    *   `status` — результат выполнения.
*   **Особенность:** Обычно используются два разных буфера: один для отправки, второй для приема.

**Разновидность:** `MPI_Sendrecv_replace`
*   **Назначение:** Если нужно обменяться данными, используя **один и тот же буфер** (т.е. послать свои данные и положить принятые на место старых).
*   **Логика:** Выполняет замену данных в буфере.

> *Примечание:* Эти функции являются блокирующими. Неблокирующих аналогов для `MPI_Sendrecv` в стандарте MPI не предусмотрено (на момент лекции).

### 6. Итоги по парным операциям

*   **Коллективные операции** (рассылка, сбор, редукция) могут работать даже с одним процессом в коммуникаторе (например, при запуске программы без `mpirun`).
*   **Парные операции** требуют явного указания источника и получателя. Если программа запущена с одним процессом, парные операции могут не сработать, если в коде жестко прописаны ранги, которых не существует.
*   Парные операции можно реализовывать как в **блокирующем**, так и в **неблокирующем** режиме. Неблокирующий режим сложнее, но позволяет совмещать обмен с вычислениями.

## ЧАСТЬ 3: ПРОИЗВОДНЫЕ ТИПЫ ДАННЫХ (Derived Datatypes)

### 1. Введение и мотивация

**Проблема:** Стандартные типы MPI (`MPI_INT`, `MPI_DOUBLE`) предполагают, что данные в памяти лежат **непрерывно** (подряд). Но часто данные расположены сложнее.

**Пример:** Матрица в языке C хранится по строкам. Если мы хотим отправить **столбец** матрицы, элементы этого столбца в памяти расположены с шагом, равным длине строки.

**Способы решения:**
1.  **Множественные `MPI_Send`:** Отправлять каждый элемент отдельно в цикле. **Минус:** Очень медленно из-за накладных расходов на каждую операцию.
2.  **Упаковка (Packing/Serialization):** Вручную скопировать данные в непрерывный буфер, отправить одним сообщением, а на приемнике распаковать. **Минус:** Требует дополнительной памяти и времени на копирование.
3.  **Производные типы данных (Derived Datatypes):** Создать описание того, как данные расположены в памяти, и использовать это описание в функциях отправки/приема. **Плюс:** Эффективно, не требует лишнего копирования.

### 2. Основы: Карта типа (Type Map)

Производный тип данных в MPI — это не тип в привычном смысле (как `int` или `float`), а **описание карты памяти**.

**Карта типа** — это набор пар: `(базовый_тип, смещение)`.

**Пример:**
Пусть в памяти есть три переменные:
*   `a` (double) по адресу 24
*   `b` (double) по адресу 40
*   `n` (int) по адресу 48

Мы можем описать этот набор как карту:
1.  `(MPI_DOUBLE, 0)` — если за точку отсчета взять адрес `a` (24).
2.  `(MPI_DOUBLE, 16)` — `b` находится на 16 байт дальше `a` (40 - 24 = 16).
3.  `(MPI_INT, 24)` — `n` находится на 24 байта дальше `a` (48 - 24 = 24).

> *Важно:* Порядок пар в карте не важен. Главное — правильно указать смещения относительно выбранной точки отсчета.

**Характеристики типа:**
*   **Нижняя граница (LB):** Минимальное смещение в карте.
*   **Верхняя граница (UB):** Максимальное смещение + размер типа на этом смещении.
*   **Протяженность (Extent):** `UB - LB`. Это количество байт, которое нужно выделить для одного элемента данного производного типа.
*   **Размер (Size):** Реальное количество байт, которое занимают данные (без учета «дырок»).
*   **Выравнивание (Alignment):** Для эффективной работы память может выравниваться (например, до 8 или 16 байт). Это влияет на протяженность.

**Функция `MPI_Type_extent`:** Позволяет узнать протяженность типа.

### 3. Способы создания производных типов

В MPI есть несколько функций для создания производных типов. Мы рассмотрим три основных:

#### А. Векторный тип (`MPI_Type_vector`)
**Назначение:** Для данных, которые расположены регулярными блоками с постоянным шагом.

**Пример:** Столбец матрицы или несколько подряд идущих столбцов.

**Синтаксис:**
`int MPI_Type_vector(int count, int blocklength, int stride, MPI_Datatype oldtype, MPI_Datatype *newtype);`

*   `count` — количество блоков.
*   `blocklength` — количество элементов в каждом блоке.
*   `stride` — расстояние (в элементах) между началами соседних блоков.
*   `oldtype` — базовый тип (например, `MPI_DOUBLE`).
*   `newtype` — указатель, куда будет записан новый тип.

**Пример (столбец матрицы N x N):**
*   `count = N` (количество строк).
*   `blocklength = 1` (один элемент в строке).
*   `stride = N` (шаг между элементами столбца равен длине строки).
*   `oldtype = MPI_DOUBLE`.

#### Б. Индексный тип (`MPI_Type_indexed`)
**Назначение:** Для данных, которые расположены нерегулярно, но с известными смещениями.

**Пример:** Выборка произвольных элементов из массива.

**Синтаксис:**
`int MPI_Type_indexed(int count, int *blocklengths, int *displacements, MPI_Datatype oldtype, MPI_Datatype *newtype);`

*   `count` — количество блоков.
*   `blocklengths` — массив длин блоков.
*   `displacements` — массив смещений для каждого блока.
*   `oldtype` — базовый тип.
*   `newtype` — новый тип.

#### В. Структурный тип (`MPI_Type_struct` / `MPI_Type_create_struct`)
**Назначение:** Самый общий случай. Позволяет описать произвольную структуру данных.

**Пример:** Структура в C с разными типами полей.

**Синтаксис (современный):**
`int MPI_Type_create_struct(int count, int *blocklengths, MPI_Aint *displacements, MPI_Datatype *types, MPI_Datatype *newtype);`

*   `count` — количество полей.
*   `blocklengths` — массив длин полей.
*   `displacements` — массив смещений полей (в байтах).
*   `types` — массив типов полей.
*   `newtype` — новый тип.

> *Примечание:* Для вычисления смещений в байтах часто используется функция `MPI_Get_address`.

### 4. Использование производных типов

1.  **Создание:** Вызывается функция создания типа (например, `MPI_Type_vector`).
2.  **Фиксация:** `MPI_Type_commit(&newtype)` — обязательный шаг перед использованием.
3.  **Использование:** Новый тип можно использовать в любых операциях обмена (`MPI_Send`, `MPI_Recv`, `MPI_Bcast` и т.д.) как обычный тип.
4.  **Освобождение:** `MPI_Type_free(&newtype)` — после завершения работы.

> *Важно:* При парном обмене производный тип должен быть создан **и на отправителе, и на получателе** (или должна быть уверенность, что описание типов совпадает).

## ЧАСТЬ 3 (Продолжение): Производные типы данных

### 4. Использование производных типов (Продолжение)

**Важное замечание о точке отсчета:**
Созданный производный тип (например, для половины матрицы) описывает **структуру**, но не привязывается к конкретному адресу. Когда вы используете этот тип в операции отправки, вы указываете адрес начала данных.
*   Если указать адрес **нулевого элемента нулевой строки**, будет отправлена **левая половина** матрицы.
*   Если указать адрес **элемента с индексом `n/2` в нулевой строке**, будет отправлена **правая половина**.
*   Смещая точку отсчета, можно передавать любую часть матрицы.

**Обобщение:** Этот подход работает не только для двумерных матриц, но и для тензоров любой размерности. Главное — правильно рассчитать смещения в памяти.

**Создание подмассивов (`MPI_Type_create_subarray`):**
Для вырезания подмассивов из многомерных массивов (например, двумерной матрицы из трехмерной) используется функция `MPI_Type_create_subarray`.
*   **Параметры:**
    *   `ndims` — размерность исходного массива.
    *   `array_of_sizes` — количество элементов в каждой размерности исходного массива (например, `[10, 10, 10]`).
    *   `array_of_subsizes` — размеры подмассива.
    *   `array_of_starts` — индексы начального элемента подмассива.
    *   `order` — порядок размещения в памяти (`MPI_ORDER_C` для языка C, `MPI_ORDER_FORTRAN` для Фортрана).
    *   `oldtype` — базовый тип элемента.
    *   `newtype` — новый тип.

### 5. Пример: Верхняя треугольная матрица (индексный тип)

**Задача:** Описать верхнюю треугольную матрицу с помощью `MPI_Type_indexed`.

**Логика:**
*   Матрица `N x N`.
*   `count = N` (количество строк).
*   `blocklengths` — массив длин блоков: `[N, N-1, N-2, ..., 1]`.
*   `displacements` (offset) — массив смещений от начала: `[0, N+1, 2N+2, ...]`. Смещение для каждой следующей строки увеличивается на `N+1` (длина строки + 1, чтобы пропустить нулевой элемент).

**Важный момент о приеме данных:**
Если вы отправляете верхнюю треугольную матрицу как один элемент производного типа, на **принимающем процессе** память должна быть выделена **в полном объеме** (как под исходную матрицу `N x N`).
*   Данные будут размещены по тем же индексам и с теми же промежутками.
*   Элементы, которые не передавались (нижний треугольник), останутся в памяти неинициализированными («мусором»).
*   Это неэкономично по памяти, но удобно, если дальше в программе вы работаете только с верхним треугольником.

**Сравнение с `MPI_Scatter`:**
*   При использовании `MPI_Scatter` каждый процесс (кроме корневого) может выделить память ровно под принимаемые данные.
*   При использовании производных типов для передачи сложных структур память на приемнике часто выделяется «с запасом».

### 6. Структурный тип (`MPI_Type_create_struct`)

**Самый общий случай.** Позволяет описать произвольную структуру данных (например, объект класса).
*   **Параметры:**
    *   `count` — количество блоков.
    *   `blocklengths` — массив количества элементов в каждом блоке.
    *   `displacements` — массив смещений (в байтах) для каждого блока.
    *   `types` — массив типов для каждого блока.
    *   `newtype` — новый тип.
*   **Применение:** Можно описать только те поля объекта, которые нужно передать, пропустив ненужные.

**Эволюция функций:**
*   В первых стандартах MPI функции назывались иначе (например, `MPI_Type_struct`).
*   Начиная с MPI-2, они были переименованы в `MPI_Type_create_*`.
*   Параметры, которые были скалярными в векторном типе, в структурном становятся массивами.

### 7. Регистрация и освобождение типов

1.  **Создание:** Вызов функции создания типа.
2.  **Регистрация:** `MPI_Type_commit(&newtype)` — обязательна перед использованием.
3.  **Использование:** Тип можно использовать в любых операциях обмена.
4.  **Освобождение:** `MPI_Type_free(&newtype)` — снимает регистрацию. Рекомендуется вызывать для всех созданных типов, чтобы избежать утечек памяти в runtime-части MPI.

## ЧАСТЬ 4: РУЧНАЯ УПАКОВКА И РАСПАКОВКА ДАННЫХ

Альтернатива производным типам — **явная упаковка** данных в непрерывный буфер и **распаковка** на приемнике.

### 1. Упаковка (`MPI_Pack`)

**Функция:** `int MPI_Pack(void *inbuf, int incount, MPI_Datatype datatype, void *outbuf, int outsize, int *position, MPI_Comm comm);`

*   **Назначение:** Копирует данные из `inbuf` в непрерывный буфер `outbuf`.
*   **Параметры:**
    *   `inbuf` — адрес данных, которые нужно упаковать.
    *   `incount` — количество элементов.
    *   `datatype` — тип данных.
    *   `outbuf` — буфер, куда складываются данные.
    *   `outsize` — размер буфера `outbuf` в байтах.
    *   `position` — указатель на переменную, которая хранит текущее смещение в буфере. **Автоматически обновляется** после каждого вызова.
    *   `comm` — коммуникатор.
*   **Особенность:** Функцию можно вызывать несколько раз подряд для упаковки разных данных в один буфер. `position` будет автоматически сдвигаться.

**Пример:**
```c
int position = 0;
MPI_Pack(&a, 1, MPI_DOUBLE, buf, bufsize, &position, MPI_COMM_WORLD);
MPI_Pack(&b, 1, MPI_DOUBLE, buf, bufsize, &position, MPI_COMM_WORLD);
MPI_Pack(&n, 1, MPI_INT, buf, bufsize, &position, MPI_COMM_WORLD);
```
После этого буфер `buf` содержит упакованные данные, которые можно отправить одним сообщением.

### 2. Определение размера буфера (`MPI_Pack_size`)

**Функция:** `int MPI_Pack_size(int incount, MPI_Datatype datatype, MPI_Comm comm, int *size);`

*   **Назначение:** Позволяет узнать, сколько памяти (в байтах) потребуется для упаковки данных.
*   **Применение:** Используется для выделения буфера достаточного размера перед вызовом `MPI_Pack`.
*   **Важно:** Для производных типов учитывается их протяженность (extent).

### 3. Распаковка (`MPI_Unpack`)

**Функция:** `int MPI_Unpack(void *inbuf, int insize, int *position, void *outbuf, int outcount, MPI_Datatype datatype, MPI_Comm comm);`

*   **Назначение:** Извлекает данные из непрерывного буфера `inbuf` и размещает их в памяти по нужным адресам.
*   **Параметры:**
    *   `inbuf` — буфер с упакованными данными.
    *   `insize` — размер буфера.
    *   `position` — текущее смещение (автоматически обновляется).
    *   `outbuf` — адрес, куда нужно поместить данные.
    *   `outcount` — количество элементов.
    *   `datatype` — тип данных.
    *   `comm` — коммуникатор.
*   **Порядок:** Данные распаковываются в том же порядке, в котором они были упакованы.

**Пример:**
```c
int position = 0;
MPI_Unpack(buf, bufsize, &position, &a, 1, MPI_DOUBLE, MPI_COMM_WORLD);
MPI_Unpack(buf, bufsize, &position, &b, 1, MPI_DOUBLE, MPI_COMM_WORLD);
MPI_Unpack(buf, bufsize, &position, &n, 1, MPI_INT, MPI_COMM_WORLD);
```

### 4. Сравнение подходов: Упаковка vs. Производные типы

| Критерий | Упаковка (MPI_Pack) | Производные типы |
| :--- | :--- | :--- |
| **Память** | Требуется дополнительный буфер для упаковки. | Дополнительная память не требуется (данные читаются напрямую). |
| **Время** | Требуется время на копирование данных в буфер и обратно. | Накладные расходы на создание типа, но копирование не требуется. |
| **Сложность** | Проще в реализации для нерегулярных данных. | Сложнее в описании, но эффективнее. |
| **Гибкость** | Позволяет легко менять логику обработки данных. | Требует точного описания структуры памяти. |

> *Вывод лектора:* Какой вариант быстрее — упаковка или производные типы — **зависит от конкретной задачи**. Это можно определить только **экспериментально**. Поэтому в MPI поддерживаются оба подхода.
