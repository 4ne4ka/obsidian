# Конспект лекции 02: Коллективные и парные взаимодействия в MPI

## Введение и повторение
**Основы MPI:**
*   MPI — это библиотека функций, типов данных и констант.
*   **Базовые функции:** Из сотен функций можно выделить 6 базовых.
    *   `MPI_Init` — инициализация.
    *   `MPI_Finalize` — завершение.
    *   `MPI_Comm_size` — количество процессов в коммуникаторе.
    *   `MPI_Comm_rank` — ранг (номер) текущего процесса (от 0 до N-1).
    *   `MPI_Send` — отправка сообщения.
    *   `MPI_Recv` — прием сообщения.
*   **Коммуникатор:** По умолчанию используется `MPI_COMM_WORLD`. Можно создавать свои коммуникаторы. Количество процессов увеличивать можно, удалять — нельзя.
*   **Параметры передачи данных:** Адрес буфера, количество элементов (`count`), тип данных MPI (`type`), ранг получателя/отправителя, тег (`tag`), коммуникатор.
*   **Особенности `MPI_Recv`:** Блокирует процесс до получения сообщения. Можно использовать `MPI_ANY_SOURCE` (принимать от любого) и `MPI_ANY_TAG`.

## Раздел 1: Коллективное взаимодействие

### 1.1. Широковещательный обмен (Broadcast) — `MPI_Bcast`
*   **Назначение:** Рассылка копии данных от одного процесса (корневого/root) всем остальным процессам коммуникатора.
*   **Замена:** Заменяет цикл из `MPI_Send`, который неэффективен (все ждут нулевой процесс).
*   **Синтаксис:**
    ```c
    int MPI_Bcast(void *buf, int count, MPI_Datatype type, int root, MPI_Comm comm);
    ```
    *   `buf` — адрес буфера (для root — откуда брать, для остальных — куда писать).
    *   `count` — число элементов.
    *   `type` — тип данных.
    *   `root` — номер процесса-источника.
    *   `comm` — коммуникатор.
*   **Важно:** Это **коллективная** операция. Её должны вызвать **все** процессы коммуникатора, независимо от ранга (даже если они ничего не отправляют). Буфер имеет разное назначение: для root — источник, для остальных — приемник.
*   **Эффективность:** Реализация MPI обычно использует древовидную схему (бинарное дерево), что сокращает время рассылки с O(N) до O(log N). Учитываются топологии узлов (общая память).

### 1.2. Операции редукции — `MPI_Reduce`
*   **Назначение:** Сбор данных со всех процессов, применение к ним заданной операции и помещение результата в один (корневой) процесс.
*   **Синтаксис:**
    ```c
    int MPI_Reduce(void *sendbuf, void *recvbuf, int count, MPI_Datatype type, MPI_Op op, int root, MPI_Comm comm);
    ```
    *   `sendbuf` — буфер с отправляемыми данными.
    *   `recvbuf` — буфер для результата (только для root).
    *   `op` — операция (например, `MPI_SUM`, `MPI_MAX`).
    *   `root` — процесс, получающий результат.
*   **Базовые операции:** `MPI_MAX`, `MPI_MIN`, `MPI_SUM`, `MPI_PROD`, логические (`MPI_LAND`, `MPI_BAND`), исключающее ИЛИ (`MPI_LXOR`, `MPI_BXOR`), а также `MPI_MAXLOC`, `MPI_MINLOC` (поиск максимума/минимума и его индекса).
*   **Важно:** Все процессы должны вызывать функцию с одинаковыми параметрами `count`, `type`, `op`, `root`, `comm`. Данные передаются всеми, но результат получает только root.

### 1.3. Пример: Вычисление числа π
*   **Математическая основа:** Интеграл \(\pi = \int_{0}^{1} \frac{4}{1+x^2} dx\).
*   **Метод:** Метод прямоугольников.
*   **Параллельная схема (циклическая):**
    *   Процесс 0 считывает `n` (число интервалов).
    *   `n` рассылается всем через `MPI_Bcast`.
    *   Каждый процесс вычисляет свою часть суммы (циклически: i = ProcRank + 1; i <= n; i += ProcNum).
    *   Локальные суммы собираются на процессе 0 с помощью `MPI_Reduce` с операцией `MPI_SUM`.
    *   Процесс 0 выводит результат.
*   **Код:** (Стр. 12-13 PDF) Демонстрирует использование `MPI_Bcast` и `MPI_Reduce` в главном цикле.

### 1.4. Рассылка и сбор данных (Scatter/Gather)
*   **`MPI_Scatter`:** Распределяет данные от одного процесса всем остальным.
    ```c
    int MPI_Scatter(void *sbuf, int scount, MPI_Datatype stype, void *rbuf, int rcount, MPI_Datatype rtype, int root, MPI_Comm comm);
    ```
    *   `sbuf` — буфер источника (только root).
    *   `scount` — количество элементов, передаваемых **каждому** процессу.
    *   `rbuf` — буфер приема (у всех).
    *   *Вариант:* `MPI_Scatterv` — если размеры сообщений различаются.
*   **`MPI_Gather`:** Собирает данные от всех процессов в один (обратная операция).
    ```c
    int MPI_Gather(void *sbuf, int scount, MPI_Datatype stype, void *rbuf, int rcount, MPI_Datatype rtype, int root, MPI_Comm comm);
    ```
    *   `rbuf` — буфер сбора (только root).
    *   *Вариант:* `MPI_Gatherv` — если размеры сообщений различаются.
*   **`MPI_Allgather`:** Сбор данных, при котором результат получают **все** процессы.
*   **`MPI_Alltoall`:** Каждый процесс отправляет данные каждому. (Стр. 22 PDF).

### 1.5. Пример: Вычисление скалярного произведения
*   **Задача:** \(S = \sum_{i=1}^{n} a_i \cdot b_i\).
*   **Схема:**
    1.  Векторы `a` и `b` разбиваются на блоки.
    2.  Блоки рассылаются процессам через `MPI_Scatter`.
    3.  Каждый процесс вычисляет частичное скалярное произведение.
    4.  Частичные суммы собираются на процессе 0 через `MPI_Reduce`.
*   **Код:** (Стр. 19-20 PDF). Важный момент: при нецелом делении `n` на `ProcNum` необходимо использовать `MPI_Scatterv` или дополнять нулями.

### 1.6. Синхронизация — `MPI_Barrier`
*   **Назначение:** Блокирует выполнение процесса до тех пор, пока все процессы коммуникатора не вызовут эту функцию.
*   **Синтаксис:** `int MPI_Barrier(MPI_Comm comm);`

## Раздел 2: Взаимодействие между двумя процессами

### 2.1. Режимы взаимодействия (Режимы Send)
1.  **Стандартный (Standard):** `MPI_Send`. Блокирует отправителя до тех пор, пока буфер не будет безопасно использован (сообщение может быть скопировано в системный буфер или получено). Состояние сообщения неопределенно.
2.  **Синхронный (Synchronous):** `MPI_Ssend`. Завершается только после подтверждения получения сообщения принимающим процессом. Самый медленный, но самый надежный.
3.  **По готовности (Ready):** `MPI_Rsend`. Может использоваться только если процесс приема уже инициирован. Самый быстрый, но требует осторожности.
4.  **Буферизированный (Buffered):** `MPI_Bsend`. Использует дополнительный буфер, созданный пользователем. Завершается сразу после копирования в буфер.
    *   Для использования нужен `MPI_Buffer_attach` и `MPI_Buffer_detach`.

**Рекомендации:** Стандартный и буферизированный — для коротких сообщений. Синхронный — для длинных.

### 2.2. Неблокирующее взаимодействие
*   **Префикс `I` (Immediate):** `MPI_Isend`, `MPI_Irecv`, `MPI_Issend` и т.д.
*   **Синтаксис:** Добавляется параметр `MPI_Request *request`.
*   **Проверка завершения:**
    *   `MPI_Test` — неблокирующая проверка (флаг завершения).
    *   `MPI_Wait` — блокирующее ожидание завершения.
    *   `MPI_Testall`, `MPI_Waitall` — для всех операций.
    *   `MPI_Testany`, `MPI_Waitany` — для любой из операций.
*   **Схема:** `MPI_Irecv(...)` -> Вычисления -> `MPI_Wait(...)`. Позволяет совмещать обмен данными с вычислениями.

### 2.3. Совмещенные прием и передача
*   **`MPI_Sendrecv`:** Позволяет одновременно отправить и принять сообщение, избегая взаимоблокировок (deadlock).
    ```c
    int MPI_Sendrecv(void *sbuf, int scount, MPI_Datatype stype, int dest, int stag, void *rbuf, int rcount, MPI_Datatype rtype, int src, int rtag, MPI_Comm comm, MPI_Status *status);
    ```
*   **`MPI_Sendrecv_replace`:** Использует один буфер для приема и передачи.

# Конспект лекции 02 (Часть 2): Коллективные операции (Scatter, Gather, Reduce)

## 1. Углубление в операцию `MPI_Reduce` (Редукция)

**Назначение:** Сбор данных со всех процессов и применение к ним заданной операции с помещением результата в один (корневой) процесс.

**Синтаксис:**
```c
int MPI_Reduce(void *sendbuf, void *recvbuf, int count, MPI_Datatype type, MPI_Op op, int root, MPI_Comm comm);
```

**Детали параметров:**
*   `sendbuf` — буфер, который **должен существовать у каждого процесса**. Он заполнен данными, которые будут участвовать в операции.
*   `recvbuf` — буфер для результата. Существует **только у корневого процесса** (root).
*   `count` — количество элементов (одинаковое для всех).
*   `type` — тип данных (одинаковый для всех).
*   `op` — операция, выполняемая поэлементно (компонентно). Например, `MPI_SUM`, `MPI_MAX`, `MPI_MIN`, `MPI_PROD`, логические операции.
*   `root` — ранг процесса-приемника.
*   `comm` — коммуникатор.

**Эффективность:**
*   Реализация MPI эффективнее, чем ручной цикл `Send/Recv` с последующей обработкой.
*   **Начиная с 4 процессов** выигрыш становится заметным. Для 2-3 процессов разница минимальна, так как сложно построить эффективное дерево передач.

**Пример работы (на пальцах):**
*   Пусть у нас 3 процесса и по 4 элемента в массиве `x`.
*   Вызываем `MPI_Reduce` с `MPI_SUM`, `root = 2`.
*   На процессе 2 (root) в массиве `y` окажутся поэлементные суммы:
    *   `y[0] = x0[0] + x1[0] + x2[0]`
    *   `y[1] = x0[1] + x1[1] + x2[1]`
    *   и так далее.
*   Если `count = 1` (скаляр), то указывается адрес одной переменной.

## 2. Пример: Вычисление числа π (Детальный разбор)

**Ситуация:** Много вычислений, мало пересылок. Данные не пересылаются массивами, только скалярные значения.

**Математическая основа:**
*   Вычисление интеграла \(\pi = \int_{0}^{1} \frac{4}{1+x^2} dx\) методом прямоугольников (центральных).
*   Отрезок интегрирования разбивается на `n` частей.

**Схема параллелизации:**
*   Используется **циклическая схема** распределения вычислений.
*   Каждый процесс вычисляет свою часть отрезков: `i = ProcRank + 1; i <= n; i += ProcNum`.
*   Поскольку данные не пересылаются, а только вычисляются, это позволяет избежать накладных расходов на передачу массивов.

**Разбор кода:**
1.  **Инициализация:** Подключение `mpi.h`, инициализация `MPI_Init`.
2.  **Ввод данных:** Процесс 0 запрашивает у пользователя количество отрезков `n` (через `scanf`). Это иллюстративный режим.
3.  **Рассылка `n`:** Процесс 0 рассылает `n` всем остальным с помощью `MPI_Bcast`.
4.  **Вычисление:**
    *   `h = 1.0 / n` — длина одного отрезка.
    *   Локальная сумма `sum = 0`.
    *   Цикл: `for (i = ProcRank + 1; i <= n; i += ProcNum)`.
    *   Вычисление `x = h * (i - 0.5)` — центр прямоугольника.
    *   `sum += f(x)`.
    *   После цикла: `mypi = h * sum` — площадь, обработанная данным процессом.
5.  **Редукция:** `MPI_Reduce(&mypi, &pi, 1, MPI_DOUBLE, MPI_SUM, 0, MPI_COMM_WORLD)`.
    *   Все процессы отправляют свой `mypi`.
    *   Процесс 0 получает итоговое `pi`.
6.  **Вывод:** Процесс 0 выводит результат и время.
7.  **Завершение:** `MPI_Finalize`.

**Важные замечания лектора:**
*   Умножение на `h` вынесено за цикл суммирования для экономии вычислений.
*   Схема с `ProcRank + 1` и `i - 0.5` соответствует центральным прямоугольникам.
*   При увеличении `n` точность растет, а ускорение приближается к линейному (так как вычислений много, а пересылок мало).
*   Программа работает в цикле `while (!done)`, пока пользователь не введет `n <= 0`.

## 3. Операция `MPI_Scatter` (Рассылка данных)

**Назначение:** Распределение данных от одного процесса (root) всем остальным процессам. Каждому процессу достается своя порция.

**Синтаксис:**
```c
int MPI_Scatter(void *sbuf, int scount, MPI_Datatype stype, void *rbuf, int rcount, MPI_Datatype rtype, int root, MPI_Comm comm);
```

**Ключевые особенности:**
*   **Две тройки параметров:**
    *   `sbuf, scount, stype` — описывают **исходные данные на процессе root**. `scount` — это размер порции, которая достанется **каждому** процессу (включая root).
    *   `rbuf, rcount, rtype` — описывают **принимаемые данные** на каждом процессе.
*   **Важное отличие от Broadcast:** В `MPI_Bcast` второй параметр — общий размер буфера. В `MPI_Scatter` второй параметр — **размер порции для одного процесса**.
*   **Условие применимости:** `MPI_Scatter` применим только тогда, когда размер исходного буфера **нацело делится** на количество процессов.
*   **Распределение:** Если `scount = 1` и процессов `P`, то каждый процесс получит по одному элементу. Если `scount = 2`, то каждый получит по два элемента (лежащих подряд в исходном массиве).

**Обработка неделимого остатка:**
*   Если данные не делятся нацело, `MPI_Scatter` использовать нельзя (можно случайно захватить чужую память).
*   **Варианты решения:**
    1.  Дополнить массив нулями (для суммирования) или единицами (для умножения) до нужного размера.
    2.  Использовать `MPI_Scatterv` (см. ниже).
    3.  Оставить «хвост» на процессе root и обработать его отдельно.

## 4. Операция `MPI_Scatterv` (Рассылка данных с разными размерами)

**Назначение:** Распределение данных, когда размер порции для каждого процесса **различается**.

**Синтаксис:**
```c
int MPI_Scatterv(void *sbuf, int *scounts, int *displs, MPI_Datatype stype, void *rbuf, int rcount, MPI_Datatype rtype, int root, MPI_Comm comm);
```

**Отличия от `MPI_Scatter`:**
*   `scounts` — **массив**, где `scounts[i]` — сколько элементов отправить процессу с рангом `i`.
*   `displs` — **массив**, где `displs[i]` — смещение в исходном буфере `sbuf`, с которого начинается порция для процесса `i`.
*   Позволяет организовать **произвольное распределение** данных (например, 30, 30, 40 элементов), если заранее известно, что нагрузка будет неравномерной.

## 5. Операция `MPI_Gather` (Сбор данных)

**Назначение:** Сбор данных со всех процессов в один (root). Операция, обратная `MPI_Scatter`.

**Синтаксис:**
```c
int MPI_Gather(void *sbuf, int scount, MPI_Datatype stype, void *rbuf, int rcount, MPI_Datatype rtype, int root, MPI_Comm comm);
```

**Ключевые особенности:**
*   **Первая тройка (`sbuf, scount, stype`):** описывает данные, которые **каждый процесс** отправляет на root. Эти параметры должны быть у всех процессов.
*   **Вторая тройка (`rbuf, rcount, rtype`):** описывает буфер на процессе root, куда собираются данные.
*   **Размер буфера:** `rbuf` должен быть равен `scount * количество_процессов` (или больше).
*   **Раскладка:** Данные раскладываются в буфере `rbuf` в соответствии с рангами процессов. То есть сначала идут данные от процесса 0, затем от процесса 1 и так далее.
*   **Важно:** В отличие от `MPI_Reduce`, здесь **не выполняется никаких операций** над данными. Они просто собираются в одном месте.

**Обработка разных размеров:**
*   Если у процессов разные объемы данных, используется `MPI_Gatherv`.
*   В `MPI_Gatherv` параметр `rcount` на процессе root становится **массивом**, где `rcount[i]` — сколько элементов принять от процесса `i`. Также используется массив смещений `displs`.

## 6. Итоги и рекомендации по использованию

*   **`MPI_Scatter` / `MPI_Scatterv`:** Используются, когда есть один выделенный процесс (обычно root), владеющий данными, и нужно раздать их порции всем остальным. Это эффективнее, чем цикл `Send`, так как реализация MPI оптимизирована.
*   **`MPI_Gather` / `MPI_Gatherv`:** Используются для сбора результатов обратно на root, если **не требуется** выполнять над ними какие-либо операции (редукцию).
*   **`MPI_Reduce`:** Используется для сбора результатов **с одновременной обработкой** (суммирование, поиск максимума и т.д.).
*   **`MPI_Bcast`:** Используется для рассылки **одинаковых** данных всем процессам.

**Общее правило:** Коллективные операции всегда эффективнее, чем ручная реализация через парные `Send`/`Recv`, начиная с определенного количества процессов (обычно от 4 и выше). Они также берут на себя заботу о корректной раскладке данных в памяти.

Вот подробный конспект заключительной части лекции, основанный на предоставленной транскрибации. Я структурировал материал, убрал повторы и дополнил его техническими деталями, которые лектор упоминает вскользь или подразумевает.

# Конспект лекции 02 (Часть 3): Примеры и дополнительные коллективные операции

## 1. Пример: Вычисление скалярного произведения

**Задача:** Вычислить \(S = \sum_{i=1}^{n} a_i \cdot b_i\).

**Схема параллельной реализации:**
1.  Векторы `a` и `b` разбиваются на примерно одинаковые блоки.
2.  Блоки рассылаются процессам с помощью `MPI_Scatter`.
3.  Каждый процесс вычисляет свою часть скалярного произведения.
4.  Частичные суммы собираются на процессе 0 с помощью `MPI_Reduce` с операцией `MPI_SUM`.

**Разбор кода:**
*   **Инициализация:** Традиционное начало, `MPI_Init`, `MPI_Comm_size`, `MPI_Comm_rank`.
*   **Ввод данных (процесс 0):**
    *   Считывается размер векторов `n`.
    *   Выделяется память под полные массивы `a` и `b` (размер `n`).
    *   Массивы заполняются (случайными числами, из файла или константами — в учебном примере).
*   **Рассылка размера:** Процесс 0 рассылает `n` всем процессам через `MPI_Bcast`.
*   **Пересчет размера порции:**
    *   `n = n / ProcNum` — каждый процесс получает свой размер порции (предполагается, что `n` делится нацело).
    *   Все процессы, кроме нулевого, выделяют память под свои части массивов `a` и `b` (размер `n`).
*   **Распределение данных:**
    *   `MPI_Scatter(a, n, MPI_DOUBLE, a, n, MPI_DOUBLE, 0, MPI_COMM_WORLD);`
    *   `MPI_Scatter(b, n, MPI_DOUBLE, b, n, MPI_DOUBLE, 0, MPI_COMM_WORLD);`
    *   **Важно:** На процессе 0 данные уже лежат в правильном месте, поэтому `MPI_Scatter` может просто скопировать их «сами в себя» или вообще пропустить копирование (в зависимости от реализации).
*   **Вычисление:**
    *   Локальная сумма `sum = 0`.
    *   Цикл `for (i = 0; i < n; i++) sum += a[i] * b[i];` — **одинаковый для всех процессов**, так как размер порции у всех одинаковый.
*   **Редукция:**
    *   `MPI_Reduce(&sum, &sum_all, 1, MPI_DOUBLE, MPI_SUM, 0, MPI_COMM_WORLD);`
    *   Процесс 0 получает итоговое скалярное произведение.
*   **Вывод:** Процесс 0 выводит результат.
*   **Завершение:** `MPI_Finalize`, очистка памяти (`delete[]`).

**Обработка неделимого остатка:**
*   Если `n` не делится нацело, `MPI_Scatter` использовать нельзя.
*   **Варианты:**
    1.  Использовать `MPI_Scatterv` (создать массивы `scounts` и `displs`).
    2.  Оставить «хвост» на процессе 0 и обработать его отдельно (например, через `MPI_Scatter` с меньшим `scount` для последнего процесса, но это требует дополнительной логики).

**Замечания лектора по коду:**
*   Код написан так, чтобы минимизировать количество условных операторов (`if`). Все процессы вызывают эффективные коллективные операции, а различия в данных скрыты внутри `MPI_Scatter`.
*   `MPI_Finalize` не обязательно ставить в самом конце. `delete[]` — это стандартная функция C++, не связанная с MPI, поэтому её можно ставить до или после `MPI_Finalize`.
*   **Ввод/вывод:** `printf` можно использовать на всех процессах (MPI обеспечит доставку на консоль), но `scanf` — **только на процессе 0** (в большинстве реализаций). В реальных параллельных программах ввод пользователя не используется; данные передаются через командную строку или файлы.

## 2. Дополнительные коллективные операции

### 2.1. `MPI_Allgather` (Сбор данных на всех процессах)

**Назначение:** Сбор данных со всех процессов так, чтобы результат оказался **на всех процессах**, а не только на корневом.

**Синтаксис:**
```c
int MPI_Allgather(void *sbuf, int scount, MPI_Datatype stype,
                  void *rbuf, int rcount, MPI_Datatype rtype,
                  MPI_Comm comm);
```

**Особенности:**
*   Нет параметра `root` — результат получают все.
*   Аналог: `MPI_Gather` + `MPI_Bcast`.
*   Может быть эффективнее, чем два отдельных вызова, так как реализация оптимизирована.

**Применение:**
*   Когда всем процессам нужно знать общую информацию (например, оценка достигнутой точности, необходимость продолжения итерационного метода).
*   Существует также `MPI_Allgatherv` для сообщений разного размера.

---

### 2.2. `MPI_Alltoall` (Взаимодействие «Каждый к каждому»)

**Назначение:** Каждый процесс отправляет данные каждому другому процессу.

**Синтаксис:**
```c
int MPI_Alltoall(void *sbuf, int count, MPI_Datatype stype,
                 void *rbuf, int rcount, MPI_Datatype rtype,
                 MPI_Comm comm);
```

**Схема работы:**
*   Если у нас `P` процессов и по `P` элементов у каждого, то результат можно представить как **транспонирование условной матрицы**.
*   **Пример:** У процесса 0 были данные `[0→0, 0→1, 0→2, ...]`. После `MPI_Alltoall` у процесса 0 окажутся данные `[0→0, 1→0, 2→0, ...]` (первый столбец).
*   Если у каждого было по `2P` элементов, то распределение идёт блоками по 2 элемента.

**Особенности:**
*   Самая сложная операция с точки зрения передачи данных.
*   Применяется редко, но может быть полезна в специфических алгоритмах.
*   Существует `MPI_Alltoallv` для сообщений разного размера.

---

### 2.3. `MPI_Allreduce` (Редукция на всех процессах)

**Назначение:** Выполнить редукцию (например, суммирование) так, чтобы результат оказался **на всех процессах**.

**Синтаксис:**
```c
int MPI_Allreduce(void *sendbuf, void *recvbuf, int count,
                  MPI_Datatype type, MPI_Op op, MPI_Comm comm);
```

**Особенности:**
*   Нет параметра `root`.
*   Аналог: `MPI_Reduce` + `MPI_Bcast`.
*   Может быть эффективнее, чем два отдельных вызова.

**Применение:**
*   Итерационные методы, где всем процессам нужно знать общую сумму/максимум для принятия решения о продолжении.

---

### 2.4. `MPI_Barrier` (Синхронизация)

**Назначение:** Блокирует выполнение процесса до тех пор, пока все процессы коммуникатора не вызовут эту функцию.

**Синтаксис:**
```c
int MPI_Barrier(MPI_Comm comm);
```

**Особенности:**
*   Минимальное количество параметров (только коммуникатор).
*   Не отправляет и не принимает данные.
*   Служит **точкой синхронизации**.

**Замечания лектора:**
*   Применяется не очень часто, так как коллективные операции и так являются точками синхронизации (хотя и не абсолютными).
*   **Почему не абсолютными?** Рассмотрим `MPI_Bcast` с древовидной реализацией. Процессы выполняют разные действия: root делает 3 пересылки, листья — 1 приём, промежуточные — 1 приём и 2 передачи. Как только процесс получил данные, его часть работы в `MPI_Bcast` закончена, и он может выйти из операции. Таким образом, полной синхронизации не происходит.
*   `MPI_Barrier` нужен, когда требуется **явная** синхронизация, например, перед замером времени или после завершения вычислительного фрагмента.

## 4. Ключевые выводы

*   **Коллективные операции** всегда предпочтительнее ручной реализации через `Send`/`Recv`, начиная с 4+ процессов.
*   **`MPI_Scatter`** требует, чтобы данные делились нацело. Иначе — `MPI_Scatterv`.
*   **`MPI_Gather`** собирает данные без обработки. **`MPI_Reduce`** — с обработкой.
*   **`MPI_Allgather`**, **`MPI_Alltoall`**, **`MPI_Allreduce`** — операции, результат которых нужен всем процессам.
*   **`MPI_Barrier`** — явная точка синхронизации, используется редко.
*   **Ввод данных** в параллельных программах должен осуществляться только на процессе 0 (или через командную строку/файлы).
*   **Вывод** можно осуществлять на всех процессах, но MPI обеспечит доставку на консоль.
