### Перечислите четыре основные концепции, которые лежат в основе MPI.

1. **Тип операции передачи данных** — как передаём данные (парные, коллективные).
    
2. **Тип данных** — что за данные (MPI_INT, MPI_DOUBLE, производные типы).
    
3. **Группа процессов** — набор рангов.
    
4. **Коммуникатор** — служебный объект, определяющий, кто участвует в операции.
    
5. **Виртуальная топология** — логическая структура связей.

### 6 базовых функций MPI:

1. `MPI_Init` — инициализация
    
2. `MPI_Finalize` — завершение
    
3. `MPI_Comm_size` — количество процессов в коммуникаторе
    
4. `MPI_Comm_rank` — ранг процесса
    
5. `MPI_Send` — отправка
    
6. `MPI_Recv` — приём

### Дайте определение понятию «коммуникатор» в MPI. Как называется коммуникатор, который создается по умолчанию при запуске программы?

**Коммуникатор** — служебный объект в MPI, который определяет, **кто входит** в операцию передачи данных. Указывается во всех операциях.

**С точки зрения программиста:** просто обозначение (обычно целое число), сопоставленное с внутренней структурой реализации.

**Содержимое коммуникатора:**

- Информация о том, где какой процесс расположен (на каком узле).
    
- Группа процессов (набор рангов от 0 до size-1).
    
- Контекст (для безопасности).
    

**Коммуникатор по умолчанию:** `MPI_COMM_WORLD` — включает **все** процессы, созданные при запуске.


### Что нужно делать, если необходимо передать данные между процессами, принадлежащими разным группам?

**Варианты:**

1. **Создать общий коммуникатор**, включающий процессы из обеих групп:
    
    - `MPI_Comm_create` или `MPI_Comm_split`.
        
    - Тогда процессы смогут общаться через этот коммуникатор.
        
2. **Использовать интеркоммуникатор** (если группы — разные MPI-программы):
    
    - `MPI_Comm_spawn` + `MPI_Intercomm_create`.
        
    - Или клиент-серверная модель: `MPI_Open_port`, `MPI_Comm_accept`, `MPI_Comm_connect`.
        
3. **Передать данные через промежуточный процесс** (если нельзя создать общий коммуникатор):
    
    - Процесс из одной группы отправляет процессу из другой через `MPI_Send`/`MPI_Recv`.
        

**Важно:** для передачи данных процессы должны быть в **одном коммуникаторе** (или в интеркоммуникаторе).


### В чем заключается главное отличие парных операций передачи данных от коллективных?

|Признак|Парные (point-to-point)|Коллективные|
|---|---|---|
|**Число участников**|2 процесса (отправитель и получатель)|≥1 процесса (все в коммуникаторе)|
|**Кто вызывает**|Только отправитель и получатель|**Все** процессы коммуникатора|
|**Синхронизация**|Нет обязательной синхронизации|Все должны вызвать операцию|
|**Примеры**|MPI_Send, MPI_Recv|MPI_Bcast, MPI_Reduce, MPI_Scatter|
|**Результат**|У получателя|У root или у всех|

### MPI_Send

MPI_Send(buf, count, datatype, dest, tag, comm);

|Параметр|Значение|
|---|---|
|`buf`|Адрес буфера с данными|
|`count`|Число элементов|
|`datatype`|Тип элементов (MPI_INT и т.д.)|
|`dest`|Ранг получателя|
|`tag`|Тег сообщения (целое число)|
|`comm`|Коммуникатор|

### MPI_Recv

MPI_Recv(buf, count, datatype, source, tag, comm, &status);

|Параметр|Значение|
|---|---|
|`buf`|Куда принять данные (память должна быть выделена!)|
|`count`|Сколько элементов принять|
|`datatype`|Тип элементов|
|`source`|От кого принимать (ранг или `MPI_ANY_SOURCE`)|
|`tag`|Тег (или `MPI_ANY_TAG`)|
|`comm`|Коммуникатор|
|`status`|Статус приёма (можно узнать source, tag, count)|

## Коллективные операции: MPI_Bcast

**Задача:** один процесс имеет данные, нужно разослать **всем** остальным.

**Решение:** `MPI_Bcast` — broadcast (рассылка).

MPI_Bcast(buf, count, datatype, root, comm);

|Параметр|Значение|
|---|---|
|`buf`|Буфер с данными (у root — заполнен, у остальных — просто выделен)|
|`count`|Число элементов|
|`datatype`|Тип элементов|
|`root`|Ранг процесса-источника|
|`comm`|Коммуникатор|

## MPI_Reduce (редукция)

**Задача:** собрать данные со всех процессов и выполнить над ними операцию (сумма, произведение, минимум, максимум и т.д.).

c

MPI_Reduce(sendbuf, recvbuf, count, datatype, op, root, comm);

|Параметр|Значение|
|---|---|
|`sendbuf`|Буфер с данными у каждого процесса|
|`recvbuf`|Буфер для результата (только у root)|
|`count`|Число элементов|
|`datatype`|Тип элементов|
|`op`|Операция: `MPI_SUM`, `MPI_PROD`, `MPI_MAX`, `MPI_MIN` и др.|
|`root`|Процесс-приёмник результата|
|`comm`|Коммуникатор|


## MPI_Scatter (распределение данных)

**Задача:** один процесс (root) имеет массив, нужно раздать **разные части** разным процессам.

c

MPI_Scatter(sendbuf, sendcount, sendtype,
            recvbuf, recvcount, recvtype,
            root, comm);

| Параметр    | Значение                                                  |
| ----------- | --------------------------------------------------------- |
| `sendbuf`   | Буфер с данными (у root)                                  |
| `sendcount` | **Размер порции** для каждого процесса (не общий размер!) |
| `sendtype`  | Тип элементов                                             |
| `recvbuf`   | Буфер для приёма (у всех)                                 |
| `recvcount` | Сколько принять (обычно = sendcount)                      |
| `recvtype`  | Тип                                                       |
| `root`      | Процесс-источник                                          |
| `comm`      | Коммуникатор                                              |

## MPI_Scatterv (распределение с разными порциями)

**Задача:** раздать данные, когда количество элементов **не делится нацело** или порции **разные**.

c

MPI_Scatterv(sendbuf, sendcounts, displs, sendtype,
             recvbuf, recvcount, recvtype,
             root, comm);

|Параметр|Значение|
|---|---|
|`sendcounts`|**Массив** — сколько элементов отправить каждому процессу|
|`displs`|**Массив** — смещение для каждого процесса в sendbuf|
|`recvcount`|Сколько принять (скаляр)|

**Пример:** 100 элементов, 3 процесса → sendcounts = [34, 33, 33], displs = [0, 34, 67].


## MPI_Gather (сбор данных)

**Задача:** собрать данные со всех процессов на одном (root).

c

MPI_Gather(sendbuf, sendcount, sendtype,
           recvbuf, recvcount, recvtype,
           root, comm);

|Параметр|Значение|
|---|---|
|`sendbuf`|Буфер с данными у каждого процесса|
|`sendcount`|Сколько отправить (у каждого)|
|`recvbuf`|Буфер для результата (у root)|
|`recvcount`|Сколько принять **от каждого** процесса|
|`root`|Процесс-приёмник|
|`comm`|Коммуникатор|
## MPI_Gatherv (сбор с разными порциями)

**Задача:** собрать данные, когда от разных процессов приходит **разное количество**.

c

MPI_Gatherv(sendbuf, sendcount, sendtype,
            recvbuf, recvcounts, displs, recvtype,
            root, comm);

| Параметр     | Значение                                             |
| ------------ | ---------------------------------------------------- |
| `recvcounts` | **Массив** — сколько принять от каждого процесса     |
| `displs`     | **Массив** — смещение для каждого процесса в recvbuf |
## MPI_Allgather (сбор на всех процессах)

**Задача:** собрать данные со всех процессов, но результат нужен **всем**.

c

MPI_Allgather(sendbuf, sendcount, sendtype,
              recvbuf, recvcount, recvtype, comm);

## MPI_Allreduce (редукция на всех процессах)

**Задача:** выполнить редукцию, но результат нужен **всем**.

c

MPI_Allreduce(sendbuf, recvbuf, count, datatype, op, comm);

## MPI_Alltoall (обмен всех со всеми)

**Задача:** каждый процесс отправляет **разные данные** каждому другому процессу.

c

MPI_Alltoall(sendbuf, sendcount, sendtype,
             recvbuf, recvcount, recvtype, comm);

**Схема:**

- У каждого процесса P элементов (по одному для каждого процесса).
    
- После операции процесс i получает j-й элемент от каждого процесса j.
    
- Фактически — **транспонирование** матрицы данных.

## MPI_Barrier (синхронизация)

c

MPI_Barrier(comm);

- **Точка синхронизации:** все процессы должны дойти до неё, прежде чем продолжить.

## Парные операции: 4 режима MPI_Send

### Стандартный режим (MPI_Send)

- **Блокирующая** операция.
    
- Завершается, когда данные **скопированы во внутренний буфер** MPI.
    
- После завершения буфер можно изменять/удалять.
    
- **Не гарантирует**, что сообщение доставлено или принято.
    
- Самый распространённый режим.
    

### Синхронный режим (MPI_Ssend)

- **Блокирующая** операция.
    
- Завершается, когда получатель **начал приём** (вызвал MPI_Recv).
    
- **Наибольшие гарантии** — отправитель знает, что приём начался.
    
- **Самый медленный** из четырёх режимов.
    

### Режим готовности (MPI_Rsend)

- **Блокирующая** операция.
    
- Требует, чтобы **MPI_Recv уже был вызван** получателем (жёсткая гарантия).
    
- **Самый быстрый** — минимальные задержки.
    
- **Сложно реализовать** — нужно гарантировать, что получатель готов.
    
- **Способ гарантии:** использовать MPI_Barrier перед отправкой/приёмом.
    
- **Недостаток:** если процессов >2, остальные синхронизируются зря (можно создать отдельный коммуникатор для двух процессов).
    

### Буферизованный режим (MPI_Bsend)

- **Блокирующая** операция.
    
- Требует **самостоятельного выделения буфера** на отправителе.
    
- Буфер регистрируется через `MPI_Buffer_attach`.
    
- После использования — `MPI_Buffer_detach`.
    
- Работает как стандартный Send, но данные хранятся в **своём** буфере.
    

### Сводка режимов:

|Режим|Функция|Гарантии|Скорость|Применение|
|---|---|---|---|---|
|Стандартный|MPI_Send|Копирование в буфер|Средняя|Чаще всего|
|Синхронный|MPI_Ssend|Начало приёма|Медленный|Максимальная надёжность|
|Готовности|MPI_Rsend|Recv уже вызван|Быстрый|Редко, сложно|
|Буферизованный|MPI_Bsend|Свой буфер|Средняя|Контроль памяти|

**Один вызов MPI_Recv** соответствует всем четырём режимам отправки.


## MPI_Sendrecv (обмен между двумя процессами)

**Задача:** два процесса обмениваются данными (каждый отправляет и принимает).

c

MPI_Sendrecv(sendbuf, sendcount, sendtype, dest, sendtag,
             recvbuf, recvcount, recvtype, source, recvtag,
             comm, &status);

## Производные типы данных

### Зачем нужны?

- Данные в памяти могут лежать **не подряд**.
    
- Пример: столбец матрицы (в C — по строкам).
    
- Передача по одному элементу — **медленно**.
    
- Упаковка/распаковка — **дополнительное время и память**.
    
- **Производный тип** — описание того, как данные расположены в памяти.
    

### Три подхода к передаче нерегулярных данных:

1. **Цикл Send/Recv** — медленно (много соединений).
    
2. **Упаковка (pack/unpack)** — доп. память и время.
    
3. **Производный тип** — описание структуры, одна операция.

## Основные функции создания производных типов

### MPI_Type_contiguous

c

MPI_Type_contiguous(count, oldtype, &newtype);

- **Непрерывный** тип: count элементов oldtype подряд.
    
- Применяется редко (замена count в Send).
    

### MPI_Type_vector

c

MPI_Type_vector(count, blocklength, stride, oldtype, &newtype);

- **Векторный** тип: count блоков по blocklength элементов.
    
- **stride** — расстояние между началами блоков (в элементах).
    
- **Пример:** столбец матрицы N×N: count=N, blocklength=1, stride=N.
    

### MPI_Type_create_subarray

c

MPI_Type_create_subarray(ndims, sizes, subsizes, starts, order, oldtype, &newtype);

- **Подмассив** из многомерного массива.
    
- **ndims** — размерность.
    
- **sizes** — размеры исходного массива.
    
- **subsizes** — размеры подмассива.
    
- **starts** — начальные индексы.
    
- **order** — порядок размещения (C или Fortran).
    

### MPI_Type_indexed

c

MPI_Type_indexed(count, blocklens, displs, oldtype, &newtype);

- **Индексный** тип: нерегулярные блоки.
    
- **blocklens** — размеры блоков (массив).
    
- **displs** — смещения блоков (массив).
    

### MPI_Type_create_struct

c

MPI_Type_create_struct(count, blocklens, displs, types, &newtype);

- **Структурный** тип: самый общий.
    
- Все параметры — массивы.
    
- **types** — типы элементов в блоках (могут быть разными).
    
- **Пример:** описание части объекта (класса).


## Упаковка данных (MPI_Pack / MPI_Unpack)

### MPI_Pack

c

MPI_Pack(inbuf, incount, datatype, outbuf, outsize, &position, comm);

|Параметр|Значение|
|---|---|
|`inbuf`|Откуда брать данные|
|`incount`|Сколько элементов|
|`datatype`|Тип|
|`outbuf`|Буфер для упаковки|
|`outsize`|Размер буфера (байт)|
|`position`|Текущая позиция (обновляется)|
|`comm`|Коммуникатор|

### MPI_Unpack

c

MPI_Unpack(inbuf, insize, &position, outbuf, outcount, datatype, comm);

- **Обратная операция.**
    
- `position` автоматически смещается.
    

### MPI_Pack_size

c

MPI_Pack_size(count, datatype, comm, &size);

- Сколько байт нужно для упаковки.
