# Лекция 1. Основы MPI

## 1. Введение в курс и контекст

**Цель курса:** изучение разработки параллельных программ для систем с распределённой памятью (кластеров). Весенний семестр будет посвящён системам с общей памятью.

**Почему это важно:**
- Производители процессоров упёрлись в потолок тактовой частоты (несколько ГГц) из-за физических ограничений (нагрев, энергопотребление).
- Развитие пошло по пути увеличения количества ядер, а не частоты.
- Программы, способные использовать несколько ядер/узлов, сложнее в разработке, но это оправдано для ресурсоёмких задач (пример: прогноз погоды, климатические модели).
- Существует разрыв между «железом» (процессор умеет только вычислять целые и floating-point числа) и пользовательскими задачами. Этот разрыв устраняется уровнями абстракции: аппаратура → машинный код → ассемблер → ОС → системные библиотеки → прикладные библиотеки → приложения.

**Суперкомпьютеры:**
- Это не только гигантские стойки. Бывают и мини-кластеры (например, из 4 узлов).
- Для разработки параллельных программ не обязательно иметь суперкомпьютер — технологии проектировались так, чтобы программист мог отлаживать код на обычном ПК.
- Кластеры — доминирующий тип суперкомпьютеров. Состоят из отдельных серверов (узлов), связанных скоростной сетью. Сетевая часть может быть сопоставима по стоимости с вычислительными узлами.

## 2. MPI: Основные понятия и определения

### 2.1. Модель параллельной программы
- В MPI параллельная программа — это несколько одновременно выполняемых процессов.
- Процессы могут выполняться на разных процессорах или на одном.
- Каждый процесс — это копия одного и того же программного кода (модель **SPMD** — Single Program Multiple Data, в лекции названа SPMP).
- Исходный код пишется на C или Fortran с использованием библиотеки MPI.
- Количество процессов задаётся при запуске.
- Все процессы последовательно нумеруются. Номер процесса называется **рангом**.

### 2.2. Четыре основные концепции MPI
1. **Тип операций передачи данных**
2. **Тип данных**, пересылаемых в сообщении
3. **Концепция коммуникатора**
4. **Концепция виртуальной топологии**

### 2.3. Операции передачи данных
- **Парные (point-to-point):** участвуют два процесса.
- **Коллективные (collective):** участвуют несколько процессов одновременно.

### 2.4. Коммуникатор
- Служебный объект, объединяющий группу процессов и контекст.
- Парные операции выполняются только для процессов одного коммуникатора.
- Коллективные операции применяются ко всем процессам коммуникатора.
- Указание коммуникатора обязательно для любой операции передачи данных.
- Коммуникаторы можно создавать и удалять.
- Один процесс может принадлежать разным коммуникаторам.
- По умолчанию создаётся коммуникатор **MPI_COMM_WORLD**, включающий все процессы программы.
- Для передачи данных между разными группами создаётся **intercommunicator**.

### 2.5. Типы данных
- MPI содержит широкий набор базовых типов, совпадающих с типами C и Fortran.
- Можно создавать производные типы для точного описания сообщений.

### 2.6. Виртуальная топология
- Логическая топология линий связи между процессами — полный граф (независимо от реальных физических каналов).
- MPI позволяет представить набор процессов как решётку произвольной размерности.
- Можно формировать логические (виртуальные) топологии любого типа.


## 3. Основы MPI

### 3.1. Инициализация и завершение
- Первая вызываемая функция MPI:
  ```c
  int MPI_Init(int *argc, char ***argv);
  ```
  Инициализирует среду выполнения MPI.
- Последняя вызываемая функция:
  ```c
  int MPI_Finalize(void);
  ```

**Структура параллельной программы:**
```c
#include "mpi.h"
int main(int argc, char *argv[]) {
    // Код без использования MPI
    MPI_Init(&argc, &argv);
    // Код с использованием MPI
    MPI_Finalize();
    // Код без использования MPI
    return 0;
}
```

### 3.2. Определение числа и ранга процессов
- Количество процессов:
  ```c
  int MPI_Comm_size(MPI_Comm comm, int *size);
  ```
- Ранг процесса:
  ```c
  int MPI_Comm_rank(MPI_Comm comm, int *rank);
  ```
- Обычно вызываются сразу после `MPI_Init()`.
- `MPI_COMM_WORLD` создаётся по умолчанию и представляет все процессы.
- Ранг, полученный с помощью `MPI_Comm_rank()`, уникален для каждого процесса.

**Пример:**
```c
#include "mpi.h"
int main(int argc, char *argv[]) {
    int ProcNum, ProcRank;
    MPI_Init(&argc, &argv);
    MPI_Comm_size(MPI_COMM_WORLD, &ProcNum);
    MPI_Comm_rank(MPI_COMM_WORLD, &ProcRank);
    // ...
    MPI_Finalize();
    return 0;
}
```

### 3.3. Операции отправки/получения сообщений

**Отправка:**
```c
int MPI_Send(void *buf, int count, MPI_Datatype type, int dest, int tag, MPI_Comm comm);
```
- `buf` — адрес буфера с данными.
- `count` — количество элементов данных.
- `type` — тип элементов.
- `dest` — ранг процесса-получателя.
- `tag` — тег для идентификации сообщения.
- `comm` — коммуникатор.

**Приём:**
```c
int MPI_Recv(void *buf, int count, MPI_Datatype type, int source, int tag, MPI_Comm comm, MPI_Status *status);
```
- `buf` — адрес буфера для приёма.
- `count` — количество элементов.
- `type` — тип элементов.
- `source` — ранг процесса-отправителя (можно `MPI_ANY_SOURCE`).
- `tag` — тег (можно `MPI_ANY_TAG`).
- `comm` — коммуникатор.
- `status` — указатель на структуру с информацией о результате.

**Важно:**
- Буфер должен быть достаточным, типы должны совпадать. Иначе — ошибка переполнения.
- `MPI_Recv()` — блокирующая функция. Процесс приостанавливается до получения сообщения.
- `status.MPI_SOURCE` — ранг отправителя, `status.MPI_TAG` — тег.
- `MPI_Get_count(MPI_Status *status, MPI_Datatype type, int *count)` — возвращает количество элементов типа `type` в полученном сообщении.

**Типы данных MPI для C:**

| MPI_Datatype       | C Datatype               |
| ------------------ | ------------------------ |
| MPI_CHAR           | signed char              |
| MPI_DOUBLE         | double                   |
| MPI_FLOAT          | float                    |
| MPI_INT            | int                      |
| MPI_LONG           | long                     |
| MPI_LONG_DOUBLE    | long double              |
| MPI_SHORT          | short                    |
| MPI_UNSIGNED_CHAR  | unsigned char            |
| MPI_UNSIGNED       | unsigned int             |
| MPI_UNSIGNED_LONG  | unsigned long            |
| MPI_UNSIGNED_SHORT | unsigned short           |
| MPI_PACKED         | (для упакованных данных) |

### 3.4. Оценка времени выполнения
- `double MPI_Wtime(void);` — текущий момент времени.
- `double MPI_tick(void);` — точность измерения времени.

## 4. Первая программа на MPI

**Пример (слайд 33):**
```c
MPI_Init(&argc, &argv);
MPI_Comm_size(MPI_COMM_WORLD, &ProcNum);
MPI_Comm_rank(MPI_COMM_WORLD, &ProcRank);
if (ProcRank == 0) {
    printf("Hello from %d!\n", ProcRank);
    for (int i = 1; i < ProcNum; i++) {
        MPI_Recv(&ProcRank, 1, MPI_INT, MPI_ANY_SOURCE, MPI_ANY_TAG, MPI_COMM_WORLD, &status);
        printf("Hello from %d!\n", ProcRank);
    }
} else {
    MPI_Send(&ProcRank, 1, MPI_INT, 0, 0, MPI_COMM_WORLD);
}
MPI_Finalize();
```

**Пояснение:**
- Каждый процесс узнаёт свой ранг.
- Все процессы, кроме ранга 0, отправляют свой ранг нулевому процессу.
- Нулевой процесс печатает свой ранг, затем получает сообщения от других и печатает их ранги.
- Порядок приёма сообщений не определён и может меняться от запуска к запуску.
- Чтобы обеспечить порядок, можно указать конкретный ранг в `MPI_Recv` вместо `MPI_ANY_SOURCE`.

**Коды возврата:**
- Все функции MPI возвращают код завершения.
- `MPI_SUCCESS` — успех.
- Другие значения — ошибки (например, `MPI_ERR_BUFFER`, `MPI_ERR_COMM`, `MPI_ERR_RANK`).



## 5. Введение в коллективную передачу данных

### 5.1. Проблема суммирования элементов вектора
Задача: вычислить \( S = \sum_{i=1}^{n} x_i \).

**Параллельная реализация:**
1. Разделить данные на блоки.
2. Распределить блоки по процессам.
3. В каждом процессе просуммировать свой блок.
4. Собрать частичные суммы на одном процессе.
5. Сложить их для получения общего результата.

**Неэффективный вариант:**
```c
MPI_Comm_size(MPI_COMM_WORLD, &ProcNum);
for (i = 1; i < ProcNum; i++)
    MPI_Send(&n, 1, MPI_INT, i, 0, MPI_COMM_WORLD);
```
Повторение передачи данных суммирует латентности.

### 5.2. Коллективная операция MPI_Bcast
```c
int MPI_Bcast(void *buf, int count, MPI_Datatype type, int root, MPI_Comm comm);
```
- `buf` — буфер с данными.
- `count` — количество элементов.
- `type` — тип элементов.
- `root` — ранг процесса-источника.
- `comm` — коммуникатор.

**Особенности:**
- Коллективная операция: должны вызвать все процессы коммуникатора.
- Буфер имеет разное назначение: для `root` — источник, для остальных — приёмник.
- Заменяет цикл `MPI_Send` на один вызов:
  ```c
  MPI_Bcast(&n, 1, MPI_INT, 0, MPI_COMM_WORLD);
  ```

### 5.3. Распределение данных
```c
MPI_Comm_size(MPI_COMM_WORLD, &ProcNum);
for (i = 1; i < ProcNum; i++)
    MPI_Send(&x[n/ProcNum*i], n/ProcNum, MPI_DOUBLE, i, 0, MPI_COMM_WORLD);
```
Этот код может быть реализован эффективнее (см. Лекцию 02).

**Суммирование в каждом процессе:**
```c
sum = 0.0;
for (i = 0; i < n/ProcNum; i++)
    sum += x[i];
```

### 5.4. Редукция данных
```c
int MPI_Reduce(void *sendbuf, void *recvbuf, int count, MPI_Datatype type, MPI_Op op, int root, MPI_Comm comm);
```
- `sendbuf` — буфер с отправляемыми данными.
- `recvbuf` — буфер для результата (только для `root`).
- `count` — количество элементов.
- `type` — тип элементов.
- `op` — операция редукции.
- `root` — ранг процесса, получающего результат.
- `comm` — коммуникатор.

**Основные операции редукции:**

| Операция   | Описание                   |
| ---------- | -------------------------- |
| MPI_MAX    | Максимум                   |
| MPI_MIN    | Минимум                    |
| MPI_SUM    | Сумма                      |
| MPI_PROD   | Произведение               |
| MPI_LAND   | Логическое И               |
| MPI_BAND   | Побитовое И                |
| MPI_LOR    | Логическое ИЛИ             |
| MPI_BOR    | Побитовое ИЛИ              |
| MPI_LXOR   | Исключающее логическое ИЛИ |
| MPI_BXOR   | Исключающее побитовое ИЛИ  |
| MPI_MAXLOC | Максимум и его индекс      |
| MPI_MINLOC | Минимум и его индекс       |

**Особенности:**
- Коллективная операция: все процессы коммуникатора должны вызвать.
- Все вызовы должны содержать одинаковые `count`, `type`, `op`, `root`, `comm`.
- Результат получает только `root`.
- Операция выполняется поэлементно над сообщениями.

**Пример:** вычисление суммы значений (слайд 48).

## 7. Классы вычислительных систем

### 7.1. Системы с распределённой памятью
- Состоят из отдельных серверов (узлов), связанных сетью.
- Подавляющее большинство — кластерные системы.
- Узлы обычно идентичны или разбиты на группы с одинаковыми узлами.
- Выделяются управляющие узлы, на которых установлена система управления кластером.
- Система управления решает задачи:
  - авторизации пользователей,
  - выделения вычислительных ресурсов,
  - управления заданиями (выполнением программ),
  - взаимодействия с пользователем (получение данных, выдача результатов).

### 7.2. Системы с общей памятью
- Все персональные компьютеры, ноутбуки, телефоны и большая часть окружающих устройств.
- Многопроцессорные или многоядерные системы с общей памятью.
- Количество ядер: от единиц до десятков (в серверных решениях — до первых сотен).
- Тенденция к увеличению числа ядер сохраняется.

### 7.3. Гибридные вычислительные системы
- Современные кластеры часто являются гибридными.
- Каждый вычислительный узел содержит:
  - более одного процессора (типично два),
  - в каждом процессоре — несколько ядер,
  - дополнительно могут быть установлены ускорители, сопроцессоры или графические процессоры (GPU).
- Для задействования всех вычислительных возможностей требуется специальное обучение.
- Существуют отдельные курсы по программированию для графических процессоров (в данном курсе не рассматриваются).
- Разрабатываются не только отдельные программы, но и библиотеки подпрограмм, которые можно использовать для построения других приложений.
- Пример: библиотеки линейной алгебры, которые постоянно оптимизируются под новые процессоры и вычислительные системы.


## 8. Определение термина «суперкомпьютер»

Существует несколько подходов к определению:

1. **Количественный (стоимостной):**
   - Типовая стоимость персонального компьютера — около 1000 долларов (исторически).
   - Суперкомпьютер — система стоимостью от 1–2 миллионов долларов (граница условна).

2. **Производительность:**
   - Суперкомпьютер — система с производительностью как минимум на 3 порядка (в 1000 раз) выше обычного компьютера.

3. **Качественный (по назначению):**
   - Вычислительная система, позволяющая решать задачи, которые нельзя решить на ноутбуке или персональном компьютере, даже самом мощном.
   - Дальнейшее наращивание производительности на одном сервере упирается в ограничения (материнские платы, память, охлаждение).
   - Следующий шаг — объединение нескольких серверов в систему с программно-аппаратными средствами для решения задач, специально написанных для таких систем.

4. **Утилитарный:**
   - Суперкомпьютер — вычислительная система, которая выполняет параллельные программы.
   - Обычные последовательные программы на суперкомпьютере не имеют смысла (хотя технически выполнимы).

**Практический вывод:**
- Если программа работает, например, сутки, и нужно ускорить её до часа, на обычном компьютере есть только два пути:
  1. Оптимизация алгоритмов.
  2. Оптимизация кода под конкретную аппаратуру.
- Рано или поздно эти возможности исчерпываются. Тогда единственный путь — использование множества вычислительных ресурсов (параллельные вычисления).


## 9. Алгоритмы: последовательные и параллельные

### 9.1. Определение алгоритма
- Алгоритм — точное предписание, задающее вычислительный процесс.
- Рассчитан на произвольные исходные данные.
- Направлен на получение результата, который полностью определяется исходными данными.
- Если алгоритм выполняется правильно и корректно, результат гарантирован.

### 9.2. Последовательный алгоритм
- Алгоритм, в котором выполнение предполагается строго последовательным.
- Никакие действия нельзя переставить местами.
- Либо алгоритм, явным образом рассчитанный на наличие только одного исполнителя (не рассчитан на то, что исполнителей может быть больше одного).

**Пример строго последовательного алгоритма:**
- Открывание двери ключом:
  1. Достать ключ.
  2. Вставить в замочную скважину.
  3. Повернуть 3–4 раза.
  4. Нажать на ручку.
  5. Дверь открывается.
- Ни одно действие нельзя поменять местами — результат не получится.
- Если дверей две или требуется два ключа (два человека) — задача меняется.

### 9.3. Параллельный алгоритм
- Алгоритм, в котором часть действий могут выполняться одновременно (параллельно).
- Параллельное выполнение означает физически реализуемую одновременность выполнения действий.
- Есть два или более исполнителя (ядра, процессора, вычислительных узла).
- Можно одновременно получать разные результаты или части решения задачи, если алгоритм это позволяет.

### 9.4. Чисто параллельные алгоритмы
- Возникает вопрос: существуют ли алгоритмы, в которых все действия можно выполнять одновременно?
- Ответ: да, но это частный случай. Большинство алгоритмов имеют как параллельные, так и последовательные участки.

### 9.5. Распараллеливание
- Процесс формирования алгоритмов так, чтобы в них были выделены участки, допускающие параллельное выполнение.
- Требует больше усилий, чем разработка последовательных алгоритмов.
- Оправдано для ресурсоёмких задач.

**Аналогия:**
- Табуретку можно сделать одному.
- Дом построить в одиночку можно, но тяжело и долго.
- Если привлечь больше людей, вероятность построить дом повышается.
- Но возникает необходимость определить, кто что будет делать.

### 9.6. Программы: последовательные и параллельные

**Последовательная программа:**
- Управляющая последовательность действий, реализующая алгоритм решения задачи.
- Реализована на доступном языке программирования и системе команд.
- Рассчитана только на одного исполнителя.
- Не способна использовать более одного ядра, даже если они есть.
- Программы, разрабатываемые на первых курсах, — именно такие.

**Параллельная программа:**
- Явным образом рассчитана на то, что исполнителей будет больше одного.
- При выполнении в параллельном режиме подавляющее большинство параллельных программ состоит из нескольких процессов или потоков, которые взаимодействуют друг с другом.
